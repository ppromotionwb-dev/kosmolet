# QA Космолёта (22.10.2026)

Ревью: интеграция, безопасность, UX, скорость → адверсариальная проверка (интеграция, безопасность) → починка по зонам → финальная регрессия.

## Итоги ревьюеров

### integration

Я прогнал все 10 блоков сценария на чистом профиле qa-int (порты 47510/47341/9351) и проверил два перезапуска. Загрузки и inbox писались только в тестовые папки scratchpad, системный буфер обмена был подменён. Мой экземпляр закрыт через quit, висящих electron/powershell/OpenConsole не осталось. Вместе работает основное: первый запуск без featureErrors, бэнги и подсказки, палитра, тёмная тема WB по умолчанию и её переключение на лету, JSON-дерево и copy-as-fetch (тот же ответ, 35 фильтров), все инструменты моста и пикер, кириллица в терминале, изоляция контейнеров, адблок, тема и JSON Formatter в обоих контейнерах, все 10 разделов настроек; сессия, тема и плотность переживают перезапуск. Главные проблемы стыков: клики моста Claude промахиваются при эмуляции устройства, но отчитываются об успехе; «Повторить», сниппеты и рентген виснут на ещё загружающейся странице; «Отправить в Claude» вставляет путь в голый PowerShell, если Claude уже завершился. Из известных проблем подтвердились: TypeError при выходе (2 из 2 запусков с открытой панелью), невидимый KUI.toast, выгрузка таймером вкладок с нашими DevTools (вместе с отдельным окном), пропадающая иконка вкладки, зависание pageFetch, значок ⌘ в палитре. «Исследовать элемент» при закрытой панели работает с записью сети api (2 из 2) и выделяет html при записи off. Не подтвердилось: после перезагрузки панели открывается последний инструмент, а не DevTools — это уже исправлено.

### security

Ревью безопасности «Космолёта» по модели угроз (враждебный сайт, локальный процесс к MCP-порту, скомпрометированный рендерер вкладки). Базовые механизмы изоляции сделаны крепко и подтверждены вживую: MCP-сервер правильно защищён (нет токена → 401, любой заголовок Origin → 403, чужой Host → 403, GET → 405; токен 48 симв., сравнение через timingSafeEqual по sha256 — DNS-rebinding и браузерные запросы отсечены); вкладки запускаются с sandbox+contextIsolation+nodeIntegration:false и focusOnNavigation:false; протокол kosmo:// отдаётся с corsEnabled:false и жёсткой CSP (default-src 'self' без unsafe-inline для скриптов), vendor по белому списку, без traversal; IPC-роутер корректно классифицирует отправителя по trusted frame (скомпрометированный web-рендерер остаётся 'tab' и ограничен каналами kosmo-tab:*); UI-слои нельзя увести навигацией (will-navigate preventDefault) и window.open у них задавлен. Готового XSS в привилегированных слоях (chrome/overlay/panel/внутренние страницы) я не нашёл — весь недоверенный текст рендерится через textContent/h(), а немногочисленные innerHTML используют только статические иконки или экранирование. Главная системная слабость — отсутствие разграничения прав внутри «доверенного» периметра: внутренние страницы (kosmo://history|newtab|downloads|extensions|settings) через allow:['ui','internal'] могут писать ЛЮБУЮ настройку, включая claude.claudeCommand и devtools.remoteDebugging (живой PoC), и дёргать control-plane моста (чтение Bearer-токена через bridge.command, включение access=full, запуск claude через connectClaudeCode). Это защита-в-глубину, которой нет: один будущий XSS/инъекция скрипта в любой привилегированной странице превращается в RCE и/или открытие неаутентифицированного CDP на 9222 — поэтому SEC-1/SEC-2 оценены high, хотя для срабатывания нужен скрипт в привилегированном контексте. Дополнительно: SSRF-прокси темы обходится редиректом/DNS (medium), openExternal на денилисте схем (medium), контекстное меню открывает kosmo://file://view-source по ссылке с сайта в обход web→kosmo-защиты (low), безлимитный sendSync site-theme как DoS общего main (low) и подтверждённый краш panel.send при выходе (low). Рекомендация-ядро: чувствительные ключи и операции моста разрешать только из kosmo://settings и/или с подтверждением пользователя.

Отклонено проверкой: SEC-6

### ux

Я снял на чистом профиле qa-ux все поверхности в темах cosmos и light, плюс по одному кадру graphite, terminal и compact. Всего около 120 снимков в C:\Users\Пользователь\Desktop\KOSMOLET\tools\dev-out\qa-ux\, каждый из них я сам посмотрел. Общее впечатление хорошее: единая сетка, аккуратные поповеры, полезные пустые состояния, тексты в основном короткие и по-русски, эмодзи нет. Подтвердились все 8 известных проблем. «Исследовать элемент» при закрытой панели работает, пока включена запись сети, и выделяет <html>, если запись выключена. Главное, что я нашёл сверх известного: инструмент «Хранилище» не показывает cookies без атрибута Domain (опечатка в регулярном выражении). У приглушённого текста (--k-text-faint) контраст 2,6–3,9:1, в светлой теме подсказки почти не читаются. Белый текст на акцентных кнопках даёт 3,86:1. На страницах, где хоть раз открывали DevTools, при каждом изменении размера всплывает плашка «1360px × 716px». У «Сети» отрицательные размеры «-1 Б». Остальные находки — расхождения между фичами: шапки поповеров и инструментов панели, смысл главного переключателя в поповерах «Тема» и «Блокировщик», иерархия кнопок, вид клавиш и названия одних и тех же действий. Свой экземпляр я закрыл через /quit (PID 20312 завершён), коммитов не делал. Системный буфер, диалоги и нативные меню были подменены в main, на экран пользователя ничего не выводилось.

### perf

Код не правил. Мерил на своём экземпляре qa-perf: для замеров старта взял обёртку-инструментовку из scratchpad (Module._load, лаг event loop, CPU-профили через inspector), для страниц — A/B по настройкам и временную инструментовку собранного tab-preload в своём профиле. Машина всё время была загружена на 50–100%, поэтому все цифры — медианы 3–5 повторов с указанием загрузки, а сравнения A/B шли вперемешку в новых вкладках. Главная проблема — Dark Reader, по умолчанию включённый на wildberries.ru (PERF-1, PERF-2, обе high). Он в 2,4 раза замедляет загрузку WB, добавляет 2,8 с CPU и 212 МБ на вкладку. Если WB ушёл в фон сразу после загрузки, при возврате на вкладку она висит 6–16 с. Вторая по весу проблема (PERF-3, high): после закрытия панели до четырёх фронтендов DevTools остаются в памяти, по ~90–107 МБ каждый. Простой чистый: 0,47% CPU на все процессы за 60 с при 6 загруженных вкладках, лишних опросов нет. Холодный старт с сессией: окно 1,1–3,0 с (медиана 1,97), против 0,5–0,85 с у голого Electron; наш вклад в main около 0,4 с, ещё около 0,1 с уходит на Node в preload интерфейса (sandbox:false). Память: 1 вкладка — 259 МБ (голый 127), 6 вкладок — 1094 МБ (голый 631); после выгрузки вкладок память возвращается полностью. Все 8 известных проблем подтвердились. Две из них проявляются только при условиях: favicon пропадает на github.com, но не на lenta.ru; «Исследовать элемент» при закрытой панели ломается только с devtools.capture=off. Предупреждение: при проверке «Исследовать элемент» мой вызов wc.emit('context-menu') один раз запустил в ядре код показа нативного меню. Потом я проверил: открытых всплывающих меню (#32768) нет. Мои процессы и тестовые серверы завершены, коммитов нет.
